# 解析逻辑（打开项目即生效）

用户打开本项目后，**直接输入内容即可**，不必再说「帮我翻译」或「按模板写」。

## 总流程（强制）

接到**单词**或**句子**时，顺序固定：

1. **先翻译** — 对话里立刻给出中文意思（单词：释义；句子：一句英 + 一句中）  
2. **再入库与其余操作** — 写 `entries/`、更新 `words.md`、追加 `log/`、补英文解释 / 原子意思 / 词根 / 短语 / 例句等  

不要先埋头写文件、后补翻译；用户应**先看到翻译**。

| 用户输入 | 怎么做 |
|----------|--------|
| 一个（或几个）单词 | ① 先给中文义 → ② 再按「单词五块」写入 `entries/` + 更新 `words.md` |
| 一整句 / 一段英文 | ① 先逐句英中对照 → ② 再挑难词入库；**只把较难/值得记的词**写入 `entries/` |
| 说「生成今天的 AI 新闻」 | 用已学词改写新闻 → `news/` |

## 单词 → 先翻译，再写入 vocabulary

路径：`entries/<word>.md` + 索引行到 `words.md`。

**对话回复开头**：先写清晰中文释义（1–3 个高频义），紧接着给英文解释，再给原子意思，然后才是词根 / 短语 / 句子。

五块顺序（条目内也遵守）：

1. **高频常用意思** — 每个义项：**中文 + 英文解释**（英文解释要能说清英语怎么理解这个意思）  
2. **原子意思** — 一个核心图景；说明英文取词 vs 中文取词，为什么看起来像一词多义  
3. **词根** — 词根/词缀 + 真同源 + 形近勿混  
4. **常用短语** — 搭配表  
5. **常用句子** — 每句含：原文、逐词翻译、语法拆解  

示范（原子意思怎么写）：`vocabulary/entries/plane.md`

模板：`templates/word-entry.md`

### 原子意思（强制，单词条目必有）

英文很少是「一个拼写、一堆互不相干的意思」。更常见的是：

- **英文**：描述它**动起来 / 性状**什么样（平的、推平、摊开…）  
- **中文**：描述它**看起来**是哪一类东西（飞机、刨子、平原…）  

所以同一原子会在中文里变成很多个词。写这一块时：

- 用一句话钉死原子（最好能接到拉丁/希腊）  
- 举 2–4 个中文完全不同的译法，说明它们是同一动作/性状套在不同对象上  
- **只认真同源**；同音不同拼、形近假亲戚要单独标出，不要为了好记而编假词源

## 句子 / 段落 → 先双语对照，再挑难词入库

对话（或 `sentences/`）里**必须先**给出：

1. **一句英文 + 一句中文**（按原文逐句交替；段落、列表也逐条对照）  
2. 对照完成后再：关键搭配、挑难词、写 `entries/`、更新索引与日志  

单句也一样：先英后中，再视需要拆解。

**入库规则（重要）：**

- **不要**把句中所有词都写入 `entries/`  
- **只写**较复杂、非常见、或用户不熟的词（如学术词、多义词、习语核心词）  
- 跳过：a/the、be、简单代词、极基础词（like go/see/good 等，除非用户点名要记）  
- 挑出的难词：按「单词五块」写入 `entries/`，并更新 `words.md`

模板：`templates/sentence-entry.md`
